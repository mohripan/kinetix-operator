# 2026-05-01_001 Phase 1 Local Runtime Foundations

## Summary

Implemented Phase 1 of the roadmap: a hardcoded local Kubernetes pipeline that moves events from a producer through Kafka, transforms them in a worker, and reads normalized output records from a sink.

Pipeline path:

```text
producer -> kinetix-input -> worker -> kinetix-output -> sink
```

## Added

- Go worker module under `workers`.
- Producer command that emits fake user events to Kafka.
- Worker command that consumes input records, normalizes them, writes output records, and commits offsets after successful output writes.
- Sink command for tailing or smoke-verifying transformed records.
- Shared record parsing, validation, normalization, environment config, and Prometheus metrics helpers.
- Unit tests for user event parsing and transform behavior.
- Docker image build for all three runtime binaries.
- Local kind cluster config pinned to Kubernetes `v1.32.5`.
- Strimzi-managed Kafka with `kinetix-input` and `kinetix-output` topics.
- Redis deployment and Dapr Redis state component.
- Prometheus and Grafana manifests with a basic Phase 1 dashboard.
- Demo workload manifests for producer, worker, and sink.
- PowerShell automation scripts behind Make targets:
  - `make kind-up`
  - `make deps-up`
  - `make docker-build`
  - `make docker-load`
  - `make deploy-demo`
  - `make smoke`
  - `make kind-down`

## Decisions

- Cluster name: `kinetix`.
- Namespace: `kinetix`.
- Demo image: `kinetix/demo:dev`.
- Kafka cluster: `kinetix-kafka`.
- Input topic: `kinetix-input`.
- Output topic: `kinetix-output`.
- Fake event schema: JSON user event with `id`, `user_id`, `event_type`, `timestamp`, and optional string attributes.
- Output schema: normalized JSON event with parent record ID, source topic, schema name, schema fingerprint, and processing timestamp.
- Metrics:
  - `kinetix_input_records_total`
  - `kinetix_output_records_total`
  - `kinetix_processing_errors_total`
  - `kinetix_processing_latency_seconds`

`make smoke` completed by reading five transformed records from `kinetix-output`.

## Operational Notes

- Prometheus is exposed at `http://localhost:30000`.
- Grafana is exposed at `http://localhost:30001` with `admin` / `admin`.
- `make deploy-demo` restarts producer, worker, and sink deployments so a rebuilt local `kinetix/demo:dev` image is picked up after `make docker-load`.
- The kind node image is pinned to `kindest/node:v1.32.5`. Strimzi `0.45.0` failed against Kubernetes `1.33.x` because its Fabric8 client could not parse the `emulationMajor` field in the Kubernetes version response.
- `make kind-down` tears down the local cluster.
